// 01. Problem

The Innovation Engine

IdeaForge was built to solve institutional "Lost Brilliance" a recurring pattern where high-potential student projects vanish after submission with no follow-through or community engagement.

The institution required a simple Consumer-to-Consumer (C2C) platform to pitch, refine, and collaborate on ideas within their academic community. Without such a platform, motivated innovators lacked a structured channel to find teammates, receive feedback, and gain institutional visibility.

The core challenge addressed was "Idea Stagnation." By implementing a custom gamification engine, the platform incentivizes participation through points and badges, ensuring the best concepts rise to the top via community voting and strategic tagging.

Secure Auth

Role-based access control for Admins, Staff, and Students with secure session management.

Gamification

Logic-driven reward system for submissions, votes, and collaboration milestones.

Strategic Alignment

Dynamic tagging system that links ideas to specific institutional goals or departments.

AJAX Interaction

Real-time commenting and voting without page reloads using asynchronous JavaScript.

// 04. Tech Used

Stack & Tools

The platform was built as a full-stack web application using a LAMP-adjacent stack, prioritising server-rendered PHP with asynchronous JavaScript layered on top for interactive components.

Figma was used for all UI prototyping before any implementation, ensuring the team had a shared visual reference and consistent component language throughout the build.

PHP 8.x

Server-side rendering, session management, and all backend logic including auth and gamification engine.

MySQL

Relational schema with InnoDB tables for Users, Ideas, Tags, Votes, Comments, and User Badges.

JavaScript (ES6) + AJAX

Asynchronous interactions for voting, badge unlocking, and live comment updates without page reloads.

Figma + HTML5/CSS3

UI prototyped in Figma then hand-coded with responsive CSS Grid and custom design tokens.

// 06. UI/UX Focus

Design Philosophy

The primary focus was friction reduction. Every interaction was designed to keep users in flow AJAX handles votes and badge checks silently in the background, creating a single-page feel without a full SPA framework.

A high-contrast dark theme minimises eye strain during long sessions, while the dashboard-first layout surfaces the most relevant data (trending ideas, personal stats) without any navigation overhead.

Strategic Tagging was a deliberate UX decision: by requiring category and impact tags at submission time, complex institutional data becomes easily filterable and digestible for both students and admins reviewing submissions.

Result: intuitive navigation, fully responsive across all screen sizes, and a checkout-to-collaboration flow that keeps engagement high from first visit onward.

Responsive Design

CSS Grid-based layout adapts cleanly from desktop dashboards to mobile submission forms.

Performance First

AJAX-driven interactions prevent unnecessary full-page reloads, keeping the experience snappy.
